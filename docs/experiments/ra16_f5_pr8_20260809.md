# RA16-F5-PR8 continuous Full5 experiment

## Iteration preflight

- **Gate:** Route-A Full5 functional/admission.
- **Authorized hypothesis:** increasing only Step10-A Generator streaming from
  g4 to g8 gives checkpoint backward enough headroom while preserving the PR4
  no-grad phase-resident policy.
- **Frozen baseline/contracts:** PR4 workload, trace, checkpoint, ZeRO-1,
  activation policy, Score residency, update order and EMA semantics.
- **Matching prior evidence:** PR4 and PR4-EC reproduced the same 216-MiB CUDA
  allocation failure on 16/16 ranks; allocator-cache release is rejected.
- **Supporting but non-transferable evidence:** isolated GST16-A-G8 passed with
  34.906/36.010 GiB Generator allocated/reserved peaks. It is not Full5.
- **Rejected/superseded paths:** further empty-cache fixes, ZeRO-2, changed
  resolution/trace, Score block streaming, performance claims from isolated
  pool evidence.
- **New falsifiable question:** does the exact combined Full5 graph pass with
  g8, and what already-instrumented state classes occupy each rank at the
  Step10 pre-backward boundary?
- **Decision:** GO for one functional attempt after tests, dual-host smoke and
  a fresh atomic GPU audit.

## Planned evidence

Run ID `ra16_f5_pr8_20260809_001` will preserve 16 rank traces, lifecycle
events, activation-offload events, launch/resource manifests, cgroup counters,
and the strict Route-A summary. Offline rank-memory analysis will report:

- allocated/reserved/driver-free and allocator slack;
- g8 capacity, materialization count/bytes/wall sum;
- retained-below-threshold and CPU-offloaded saved activations;
- equivalent frozen-block counts;
- an explicit unclassified residual instead of invented attribution.

One functional run cannot establish performance. Timing and high-overhead
allocator snapshots remain `Not Run`.

## Measured result

The single attempt ran from 04:29:44 to 04:42:28 UTC. It passed all pre-model
and forward gates, then failed in Step10 checkpoint recomputation at
`transformer_helios.py:1640`: a 216-MiB FP32 residual/FF temporary could not be
allocated. Direct OOM ranks were `0,1,2,4,5,8,9,12,13`; remaining ranks were
peer-terminated. Direct failures reported 37.91 GiB PyTorch allocated,
124.38--192.38 MiB driver free and 438.79 MiB reserved-unallocated. The prior
empty-cache negative means the latter is not grounds for another allocator
patch.

PR8 lowered median pre-backward allocation by exactly 2,811,154,432 bytes
relative to PR4, confirming g8 was active. It also advanced checkpoint
materialization substantially, but eventually filled the same capacity
envelope. Hence the candidate is a bounded negative rather than an
implementation no-op.

The offline storage-deduplicated analysis identified 1,368,432,736 bytes/rank
of unique below-threshold saved activations. Its dominant group is forty
`[1,2940,5120]` BF16 storages totaling 1,204,224,000 bytes. The separately
observed 5,039,686,144-byte pre-step floor is larger but remains unclassified.
Only the activation group is currently a measured lower-reuse candidate; the
floor needs an owner census.
