# RB16 Full5 split-pool pipeline

## Ordered scope

Candidate A (`RB16-F5-PIPE-MATCH16`) must pass before Candidate B
(`RB16-F5-PIPE-2G6C`) is launched. Candidate A preserves batch 16 with
Critic DP8/MB1/GAS2. Candidate B is a separately reported batch-12 Pareto
point with global `4G+12C`; it is not a direct Route-A or Candidate-A
speedup denominator.

Both start at `G2/C10/EMA10`, execute Step10-A, five Critic updates (Step10-B
and steps 11--14), five official early-step EMA updates, and stop at
`G3/C15/EMA15` before Step15-A. ZeRO-1 with CPU optimizer offload and clipping
1.0 are frozen. ZeRO-2 and implicit Score streaming fallback are closed.

## Candidate-A implementation gates

1. low-cost source/asset/trace/native-state preflight;
2. live `8G+4S+4T -> 8G+8C` transition-only run;
3. same-layout Sequential correctness and checkpoint-15;
4. same-layout Pipeline correctness and checkpoint-15;
5. paired timing only after exact gates pass.

The rank16 operation bundle is the **execution trace**. The checkpoint
`input_trace_hash` is the **state-provenance trace**. They are recorded
separately rather than incorrectly required to be equal. The native world8
checkpoint was imported from a different manifest wrapper, so preflight
requires exact equality of Generator/Critic master, module, Adam-m/v and EMA
payload hashes before it is admitted.

## Candidate-A result

**Measured, PASS (clear positive).** Candidate A uses official 384x640
SYN-FEATURE, world16 `8G+8C`, Critic DP8/MB1/GAS2/global batch 16, five Critic
updates, five official EMA updates, and the immutable post-Step10-A
`G3/C10/EMA10` transition state.

The full correctness run passed exact trace/x0/noise/timestep, Generator
invariance, C10-to-C15, EMA10-to-EMA15, queue/transport flush, and the frozen
same-layout numerical contract. Formal low-overhead timing was then run as
three fresh-process crossover pairs:

| Round | Sequential (s) | Pipeline (s) | Time reduction |
| --- | ---: | ---: | ---: |
| 1 | 354.893050 | 258.778970 | 27.0825% |
| 2 | 365.310679 | 254.510940 | 30.3303% |
| 3 | 348.748783 | 270.571476 | 22.4165% |
| Median | 354.893050 | 258.778970 | **27.0825%** |

Median throughput is 0.225420 versus 0.309144 samples/s, a 1.371414x increase.
Median sampled max node memory is 359,664,001,024 versus 358,628,737,024 bytes,
so the timing gain did not require a material host-memory increase. All six
formal runs passed; no failed formal repetition was discarded.

Warm-ups (excluded from formal statistics) were 358.864609 s Sequential and
277.079955 s Pipeline. An earlier warm-up attempt terminated because the SSH
owner received HUP; it is preserved as an operational failure and was not
counted.

The causal result covers the Critic phase from the common transition state.
Cold construction, Step10-A, transition, correctness-only SHA/state checks,
checkpoint-15 save, and data loading are outside the measured window. It is
steady-state training runtime with precomputed source-shaped features, not a
quality, convergence, or data-loader claim.

## Candidate-B status

Candidate B is now authorized by Candidate-A PASS but remains **Not Run** until
its DP12/MB1/GAS1/global-batch-12 action and correctness contracts are
preregistered. Its result will be a separate resource-throughput Pareto point;
it must not be used to restate the matched-batch Candidate-A speedup.
