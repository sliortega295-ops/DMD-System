# RA16-F5-PR12 experiment — 2026-08-09

## Preflight decision

- **Gate:** continuous Route-A Full5 functional admission.
- **Authorized hypothesis:** adding exactly four streamed Generator blocks to
  PR8 provides enough Step10 checkpoint-backward headroom to complete the
  official continuous graph.
- **Frozen baseline:** PR8 failure remains immutable; FS40 remains the accepted
  one-run functional baseline.
- **Only change:** g8 becomes
  `g12=[0,24,1,5,8,25,10,32,36,15,16,26]`.
- **Rejected paths:** ZeRO-2, empty-cache escalation, activation-policy change,
  reduced shape, altered trace, g16 auto-search and timing claims.
- **Decision:** GO after tests, dual-host smoke and exact source deployment.

## Required evidence

The attempt must preserve official 384x640 Full5 steps 10--14, ZeRO-1 CPU
optimizer, MB1/GAS1/global batch 16, five Critic and five EMA updates and exact
rank-qualified trace/version semantics. Record per-rank pre-backward memory,
materialization progress, direct OOM versus peer termination, and node cgroup
counters. Formal timing is Not Run.

## Attempt 001: instrumentation failure after the capacity gate advanced

Run `ra16_f5_pr12_20260809_001` passed dual-host topology, construction,
checkpoint-10 resume, the Step10 Generator forward/loss, checkpoint
recomputation, backward and Generator optimizer update on all ranks. The
allocator counters reported zero CUDA OOMs and neither node added a cgroup OOM
or OOM-kill event. This is new capacity evidence: unlike PR8, g12 crossed the
previous Step10 Generator-backward failure boundary.

The run then failed at the start of the Critic phase, before any Critic or EMA
update, with
`OptimizedLowVRAMManager._record() got multiple values for argument 'phase'`.
The phase-resident context passed the trace event name as the positional
`phase` argument and also passed a metadata field named `phase`. This is a
tracing field collision, not a model, optimizer, trace, lifecycle-policy or
memory failure. Sampled cgroup peaks were 717.352 GiB and 713.428 GiB; actual
OOM counters did not change. Formal timing and Full5 completion remain Not Run.

## Bounded recovery 002

The repeated-failure rule permits one non-invasive verification because the
first g12 capacity attempt exposed a previously unexecuted instrumentation
path. Runtime commit `0d66b4237ec68e8e4bc9991e543cf40a833f4e23`
only renames the conflicting trace metadata key to `resident_phase` and adds a
regression test. The frozen PR12 plan, plan SHA, checkpoint, rank-qualified
trace, ZeRO stage, activation policy and g12 lifecycle policy are unchanged.

Recovery run `ra16_f5_pr12_20260809_002` is therefore a rerun of the same
capacity question after a non-semantic fail-closed instrumentation repair; it
is not a second policy candidate. No g16 run follows automatically.

## Recovery 002 result: bounded Critic-backward capacity failure

The exact recovery passed the repaired trace entry, reproduced the complete
Step10 Generator backward/update on all 16 ranks, completed the no-grad Critic
rollout and reached `critic_loss_end`. It then failed on all 16 ranks during
Critic checkpoint recomputation/backward. Direct allocation failures were
108 MiB (3 ranks), 216 MiB (7 ranks) and 292 MiB (6 ranks); the corresponding
driver-free range was 96.38--272.38 MiB. No cgroup OOM counter changed.

This failure is downstream of the g12 Generator capacity question. Before the
Critic forward, the phase-resident g12 blocks had returned to zero resident
bytes and the whole-model manager moved Generator off GPU, then moved the
unstreamed Score model onto GPU. Median allocated memory at
`semantic_critic_pre_backward` was 33.738 GiB with only about 2.725 GiB of
driver-free capacity. Checkpoint recomputation then filled the device to
38.04--38.25 GiB allocated and failed in modulation or LoRA temporaries.

Therefore g12 is sufficient for the Step10 Generator update but the combined
Full5 plan is not admitted because the resident Score/Critic backward is the
next capacity bottleneck. Increasing Generator streaming to g16 would not
directly release this Critic-backward peak, because Generator has already been
moved off GPU at that boundary. Score block streaming or a distinct Critic
activation policy is a new mechanism and remains Not Run pending separate
authorization. Formal timing remains Not Run.
