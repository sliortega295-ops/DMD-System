# v0.2 source inventory

This document records the boundary between code that belongs in the DMD-System repository and experiment evidence that remains outside Git.

## Mainline typed runtime

`src/distillschedule/` is the stable architecture surface. It contains typed workload/model/shape specifications, compiled `ExecutionPlan`s, DMD protocol construction, model adapters, training/rollout backend interfaces, role runners, version synchronization, and `distillctl`.

## Validated compatibility mechanisms

The root `runtime/` package is retained during the strangler migration because these implementations were exercised by the real Helios/A100 research path before the typed refactor. They are not a second public API.

Current retained mechanisms include:

- audited saved-tensor activation offload;
- immutable frozen-block streaming with checkpoint/recompute interlock;
- node-shared immutable model backing;
- trainable-state-only EMA;
- DMD/critic gradient-boundary primitives;
- DeepSpeed ZeRO backend and ZeRO-3 checkpoint contracts;
- host admission and node reserve accounting;
- physical-state residency/version ownership;
- operation-keyed and nested-rollout tracing;
- Critic-only pool topology, queue, checkpoint, rank-trace and P2P transport;
- real Helios Critic-pool model/rollout primitives;
- Generator-update correctness gate;
- pre-cast checkpoint loading; and
- the bounded M1 action-library validator.

These modules are migrated into the typed runtime only after new/old operation-level parity is established.

## Profiling source

Reusable profiling code is source and belongs in Git:

- `runtime/trace.py` for phase/NVTX tracing;
- `scripts/distillschedule/run_nsys_locked.sh` for immutable Nsight capture;
- `scripts/distillschedule/nsys_profile_command.sh` for inner multi-process capture;
- world16 activity analysis/plotting utilities; and
- transfer microbenchmarks.

Profiler outputs are evidence rather than source and are excluded.

## Helios boundary

The DMD-System repository does not vendor the full upstream Helios model tree, model weights, or private cluster assets. `HeliosDMDAdapter` and the compatibility runtime assume a pinned Helios checkout is provided by the execution environment. This prevents the generic DMD runtime from becoming a fork of one model repository.

The large historical one-off launch/probe scripts are also not copied wholesale into mainline. Reusable protocol/model/runtime pieces are retained; a launcher is added only when all of its code dependencies are present in this repository and it represents an active reproducible experiment.

## Intentionally excluded artifacts

The following should remain in immutable experiment storage, releases, or the research NAS rather than normal Git history:

- model weights and training checkpoints;
- `.nsys-rep` and exported Nsight SQLite databases;
- raw rank logs and CUDA/tensor dumps;
- generated videos and evaluation outputs;
- hundreds of iteration-specific result manifests and failed launcher copies;
- temporary patches/worktree snapshots; and
- private absolute-path cluster datasets.

## Migration rule

A legacy mechanism moves from `runtime/` into `src/distillschedule/` only after the corresponding typed execution path reproduces the same operation trace, tensor identity, loss, parameter-version order, optimizer update, EMA transition, and failure/admission contract. Performance comparisons come after parity, not before it.
